# 架构与工作原理

> 阅读本文不需要读源码，但所有描述与 `go-gateway.cjs` 当前实现一一对应；二次开发时源码注释即细节文档。

## 组件总览

```
Agent 客户端（ZCode / OpenCode / 任意 OpenAI 兼容客户端）
   │  http://127.0.0.1:8788/v1   （标准 OpenAI 协议，SSE 流式）
   ▼
go-gateway.cjs（网关本体，零依赖单进程）
   │  ① 中转站优先（按模型） ② 粘性会话 ③ 限额调度 ④ 透明 failover ⑤ 备用通道兜底
   │  状态持久化：keys.json（0600，可 GO_STATE_DIR 重定位）
   ├── 中转站（任意 OpenAI 兼容端点，可选，按模型优先路由）
   ├── OpenCode Go 上游（你录入的多把 Key，逐把转发）
   └── 备用上游（任意 OpenAI 兼容端点；默认 DeepSeek 官方，可选）

go-guard.cjs（可选，独立进程）── 让网关跟随 ZCode 启停，见 guard.md
浏览器仪表盘 ── 网关直接托管 http://127.0.0.1:8788/ 静态页，见 admin-ui.md
```

对客户端来说，网关就是**一个普通的 OpenAI 兼容 endpoint**：`baseURL` 指过来、`apiKey` 填占位符即可，真实的多把 Go Key 由网关内部持有并按调度使用。

## 请求生命周期

客户端 `POST /v1/chat/completions`（可带 `x-session-id` 头）进入网关后：

0. **中转站优先层**（三层级联第 1 层，见下节）：请求模型命中某个已启用且 `active` 的中转站 → 按优先级依次尝试中转站；全部失败或未命中 → 进入 Go 池流程（本步对 Go 池完全透明）。
1. **粘性检查**：该会话已绑定 Key 且 Key 仍 `active` → 直接复用（上下文缓存不丢）。
2. **调度分配**：新会话、或原 Key 已不可用 → 按调度规则选一把 Key 并绑定（事件 `bind` / `migrate`）。
3. **转发**：请求原样转发到 OpenCode Go 上游；`retryEmptyResponse` 开启时，缓冲到第一个正文字节再开始向客户端下发（见下文「空回复重试优化」）。
4. **透明 failover**：上游 429 / 5xx 时，缓冲尚未下发的请求自动换下一把可用 Key 重试（事件 `failover`；每把 Key 至多试一次，总尝试上限 4）；failover 成功当场把会话重绑到新 Key。
5. **备用通道兜底**：failover 链耗尽、或调度时就没有任何可用 Key，且备用通道已启用并配置就绪 → 请求改走备用上游（事件 `fallback`）。
6. **如实拒绝**：备用通道也没配/也失败 → 向客户端返回真实的 429（附带最近一个窗口的恢复时间），不伪装成功。
7. **回传**：SSE 流式透传；统计用 usage 数据通过注入 `stream_options.include_usage` 获取（上游不支持时自动降级重试一次）。

## 粘性会话与缓存

OpenCode Go 的上下文缓存**跟随 Key**：换一把 Key，缓存全部失效、整段上下文重新计费。因此：

- 网关用 `x-session-id` 头做**会话粘性**：同一会话的所有请求永远走同一把 Key。
- 会话绑定的 Key 变为不可用（冷却/隔离）时，会话 `migrate` 到新 Key 并重绑——这一刻该会话的缓存注定丢失，之后的请求重新在新 Key 上积累缓存。
- 仪表盘的「缓存命中」计数 = **有缓存收益、且未因切换丢缓存的请求次数**（不是缓存 token 量）。
- 客户端不带 `x-session-id`：功能完全正常，每个请求独立按「最轻松优先」选余量最大的 Key（见下节），但没有粘性与缓存收益。

## 调度规则（怎么选 Key）

候选 = `active` 状态的 Key；优先选当前并发未达上限（`concurrencyPerKey`，默认 5）的，全部满载时放宽。候选内按请求是否带 `x-session-id` 分两套策略：

1. **会话流量（带 `x-session-id`）= 月到期优先**：月窗 `resetsAt` = 订阅续费日 = 额度到期日，到期未用完的额度随重置作废--永远先花马上作废的钱（相当于「截止期最早先做」）。无 `resetsAt`（一次性套餐）的余额不作废，排到最后当「存款」。同一到期时间下先用月额度将尽的 Key，再按周余量、5h 余量、并发数平衡。
2. **无会话流量（不带 `x-session-id`，如本地脚本直连）= 最轻松优先**：这类请求没有缓存收益且常为突发批量，路由到当前余量最大的 Key（5h 余量 → 周余量 → 月余量 → 并发少），避免集中打满一把 Key 触发 429 风暴。

> 历史说明：早期版本有「窗口将尽 90% 预切换」与「drain（月窗 ≥80% 或距续费 ≤72h 才优先）」逻辑；2026-08-24 起 drain 被**全局月到期优先**取代（drain 只是它的特例），预切换早已移除——预切换本身就会丢缓存、且 5h 窗口打满时反正会 failover。当前近限处理 = 粘性保持 + 429 实时冷却 + failover。

## 三窗口状态机

每把 Key 有 5h 滚动 / 每周 / 每月三个用量窗口（`/usage` 每 15 分钟轮询，可调），状态机：

```
录入校验通过 -> active（可用）
  |-- 5h 滚动窗口打满 -------> cooldown_rolling（到点自动恢复）
  |-- 周窗口打满 -------------> cooldown_weekly（到点自动恢复）
  |-- 月窗口耗尽 -------------> quarantined（按月窗 resetsAt 时钟自动复查回池）
  |-- 手动停用 ---------------> quarantined（reason=manual，手动启用恢复）
  |-- 401 / 退订 -------------> invalid（需手动删除重录）
```

- 冷却类状态到点自动恢复（`recover` 事件）：窗口 `resetsAt` 过点后由冷却看护**定向重查 `/usage` 即时回池**（deadline 化：精确到最早过点重排，1–60s 边界、空闲零唤醒；服务器真相驱动，不等 15 分钟轮询；网关重启后首个看护周期即补查断开期间过点的 Key，查询失败保持冷却下轮重试）；月窗隔离的 Key 在 `monthly.resetsAt` 过点后由轮询/复查自动放回（有 5 分钟缓冲防时钟误差）。
- 请求路径上的 429 **实时**驱动状态迁移：上游 `GoUsageLimitError` 的 `limitName` 按关键词归一到三窗口（实测 5h 窗口上游叫 `"5 hour"` 而非 `"rolling"`；认不出或缺失也按 5h 冷却兜底，误判最多多冷却到下一次轮询自愈）。
- **失败定向复查**：429 后 10 秒、5xx 后 30 秒定向重查 `/usage`（同 Key 60s 节流）——429 补回真实 `resetsAt`（metadata 缺失时冷却看护从「等 15 分钟轮询」升级为精确到点看护），5xx 核实额度真相；复查引发的状态迁移照走事件总线实时推送。401 已即时隔离，不复查。
- 手动「启用」/ 隔离区「一键恢复」会**实时查询上游**再放行：月窗未恢复就不放（防止放回去立刻 429）；401 则直接标 `invalid`。

## 事件总线与实时推送（SSE）

`addEvent` 是网关的领域事件总线：全部结构性状态变化（bind/cooldown/quarantine/recover/failover/fallback:*/relay:* 等 40+ 调用点）在写入事件日志的同时经 `busPublish` 推送给 SSE 订阅者；另有**流量信号 `notifyActivity`**（每请求发生、刻意不入事件日志，防高频流量把 500 条日志上限中的结构性事件挤掉）。

- `GET /api/stream`（`text/event-stream`）两类消息：`{"kind":"event","ev"}` 与 `{"kind":"activity","keyId"|"relayId"}`；25s 心跳注释帧防僵死，连接上限 8，断开即清理；设 `localToken` 时经 `?token=` 鉴权（EventSource 无法带 header）。
- 前端订阅后：**使用中光效秒级点亮**（不等刷新周期）、事件日志即时出新条目 + 750ms 防抖整页刷新；拉取轮询保留为兜底对账——**推送负责新鲜度，时钟降级为对账**。
- 15 分钟 `/usage` 轮询仍是对账器（窗口滚动数据与调度输入的事实源），不因推送而移除。

## 同池检测

上游 429 响应的 metadata 带 workspace id。多把 Key 若解析出**同一 workspace**，仪表盘标记「同池」并告警——它们共享同一个额度池，轮换无效，等于一把 Key。

## 空回复重试优化（`retryEmptyResponse`，默认关）

上游偶发「长思考后空回复」（`finish_reason=other` 或直接断流、零正文），多数客户端（含 ZCode）会判定 `empty_model_response` 且不重试。网关的对策：

- 收到第一个正文/工具调用前**缓冲整条流**；若最终是空回复，以**零字节断连**收尾——客户端视为连接层失败，走网络级自动重试。
- 正常出正文则按序交还思考+正文，之后完全直通。
- 已知取舍：缓冲期间思考内容不实时滚动（正文出现时一并显示）；「正文中途截断」不在覆盖范围。
- 默认关（完全透明直通，思考实时滚动）；近期频繁遇到空回复卡死时可在设置页打开。

## 备用通道（通用 OpenAI 协议兜底）

- **触发条件**：候选集合（非 `invalid`、非手动停用）中**没有任何 `active` Key**——即三窗口语义下全部 Key 不可用时。触发判定用本地状态，请求路径零额外网络往返。
- **转发行为**：`model` 一律改写为备用通道配置的模型；请求体按 OpenAI 标准字段白名单重建（`messages/stream/temperature/top_p/max_tokens/stop/tools/tool_choice/response_format/reasoning_effort/presence_penalty/frequency_penalty/seed/user` 等），剔除 Go 平台私有扩展字段；思考强度按配置注入 `reasoning_effort`（`reasoningEffort` 默认 `max` 拉满——Agent 场景官方推荐档，各厂取值不同，留空则透传客户端值）；流式请求注入 `include_usage`（上游 400 报错则去掉注入重试一次）。
- **自动切回**：任何一把 Go Key 恢复 `active`（窗口重置复查、轮询发现、手动恢复），下一个请求立刻切回 Go（事件 `fallback:end`，via=go-recovered）。宪法：**优先保证体验（Go 订阅额度），备用只花必要的钱**。
- **计费（`billingMode=balance`，DeepSeek 官方模式）**：金额唯一口径 = 官方 `/user/balance` 余额快照差值（人民币）。切进备用时快照一次、切回时快照一次，差值即本周期实际花费；每 15 分钟定时采样 + 仪表盘「立刻计算」按钮；网关关闭时有未结算周期，下次启动自动补结算（差值入账）。token 明细仅作参考，不用 token 估算金额。
- **`billingMode=none`**：任何不支持余额查询的 OpenAI 兼容端点（如火山方舟）选此项——不计费、不显示费用区，功能不受影响。

## 中转站优先通道（按模型优先路由）

三层级联：**中转站（按模型优先）→ OpenCode Go 池（默认）→ 备用通道（兜底）**。Go 池与备用通道的架构逐行不动，只在请求最前面加一层。

- **匹配**：每站两个模型字段——`model`（实际发给中转站的模型名）+ `goModel`（客户端请求名，用于匹配；留空 = `model`）。请求 model 与 `(goModel||model)` 精确相等才命中（应对中转站命名漂移，如大小写不一）。
- **优先级**：每站一个全局唯一正整数 `priority`（1 最优先）。手动输入冲突时**自动挤位**（目标位及其后顺延 +1，编号保持连续）；新增默认排队尾；仪表盘「自动重排」一键重编 1..N。同模型多站按优先级**完全按序试完**才进 Go 池。
- **失败分类**：`401` 立即隔离（认证失效）；`402` 或 `429/403` + 额度关键词（`insufficient_quota/quota/余额不足/额度不足/欠费` 等）立即隔离（额度耗尽）；其余失败记**连续失败计数**，**连续 5 次**隔离（任何一次成功清零）。隔离的中转站**不再参与调度**。
- **降级模型改写**：中转站全部失败后进 Go 池时，若 `goModel` 不在 Go 模型列表（网关缓存 `/v1/models`，启动 + 每轮询刷新），把转发体模型改写为该站的 `downgradeModel`（默认 `deepseek-v4-flash`，可配）；在列表则模型原样不动（客户端无感知）。缓存为空时保守不改写。
- **隔离复活 = 仅手动**：中转站额度用完不会自己回来（无 resetsAt），点「重新激活」会**先发最小探活请求**，通了才回池（连败清零），不通保持隔离并回显最新错误。这是刻意的：不做任何自动复查（与 Go 月限 Key 的 resetsAt 自动复查语义不同）。
- **快失败超时**：前置尝试响应头超时 `config.relay.headerTimeoutMs`（默认 30s），防止挂死中转站拖慢体验；流式阶段沿用 300s。流中途断不切换（与 Go key 的首字节 failover 边界一致）。
- **使用中光效**：仪表盘对「在途请求 > 0 或近 10 分钟有流量」的卡显示转圈彗星流光（Go 卡琥珀、中转站卡翠绿）。

## 存储（keys.json）

- 位置：网关脚本目录下的 `keys.json`（`GO_STATE_DIR` 可重定位）；写入时 `chmod 0600`，原子写。
- 内容：配置（调度参数、备用通道、中转站运行参数）、Key 列表与状态、**中转站列表**（baseURL/Key/模型映射/优先级/状态/连败计数）、Go 模型列表缓存、会话绑定表、事件日志、备用通道运行态（快照/采样/结算记录）。
- **真实 Key 只存在这个运行时文件里**，已 `.gitignore`，任何源码与文档不含真实密钥。
