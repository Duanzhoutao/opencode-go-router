# 架构与工作原理

> 阅读本文不需要读源码，但所有描述与 `go-gateway.cjs` 当前实现一一对应；二次开发时源码注释即细节文档。

## 组件总览

```
Agent 客户端（ZCode / OpenCode / 任意 OpenAI 兼容客户端）
   │  http://127.0.0.1:8788/v1   （标准 OpenAI 协议，SSE 流式）
   ▼
go-gateway.cjs（网关本体，零依赖单进程）
   │  ① 粘性会话  ② 限额调度  ③ 透明 failover  ④ 备用通道兜底
   │  状态持久化：keys.json（0600，可 GO_STATE_DIR 重定位）
   ├── OpenCode Go 上游（你录入的多把 Key，逐把转发）
   └── 备用上游（任意 OpenAI 兼容端点；默认 DeepSeek 官方，可选）

go-guard.cjs（可选，独立进程）── 让网关跟随 ZCode 启停，见 guard.md
浏览器仪表盘 ── 网关直接托管 http://127.0.0.1:8788/ 静态页，见 admin-ui.md
```

对客户端来说，网关就是**一个普通的 OpenAI 兼容 endpoint**：`baseURL` 指过来、`apiKey` 填占位符即可，真实的多把 Go Key 由网关内部持有并按调度使用。

## 请求生命周期

客户端 `POST /v1/chat/completions`（可带 `x-session-id` 头）进入网关后：

1. **粘性检查**：该会话已绑定 Key 且 Key 仍 `active` → 直接复用（上下文缓存不丢）。
2. **调度分配**：新会话、或原 Key 已不可用 → 按调度规则选一把 Key 并绑定（事件 `bind` / `migrate`）。
3. **转发**：请求原样转发到 OpenCode Go 上游；`retryEmptyResponse` 开启时，缓冲到第一个正文字节再开始向客户端下发（见下文「空回复重试优化」）。
4. **透明 failover**：上游 429 / 5xx 时，缓冲尚未下发的请求自动换下一把可用 Key 重试（事件 `failover`；每把 Key 至多试一次，总尝试上限 4）；failover 成功当场把会话重绑到新 Key。
5. **备用通道兜底**：failover 链耗尽、或调度时就没有任何可用 Key，且备用通道已启用并配置就绪 → 请求改走备用上游（事件 `fallback`）。
6. **如实拒绝**：备用通道也没配/也失败 → 向客户端返回真实的 429（附带最近一个窗口的恢复时间），不伪装成功。
7. **回传**：SSE 流式透传；统计用 usage 数据通过注入 `stream_options.include_usage` 获取（上游不支持时自动降级重试一次）。

## 粘性会话与缓存

OpenCode Go 的上下文缓存**跟随 Key**：换一把 Key，缓存全部失效、整段上下文重新计费。因此：

- 网关用 `x-session-id` 头做**会话粘性**：同一会话的所有请求永远走同一把 Key。
- 会话绑定的 Key 变为不可用（冷却/隔离）时，会话 `migrate` 到新 Key 并重绑——这一刻该会话的缓存注定丢失，之后的请求重新在新 Key 上积累缓存。
- 仪表盘的「缓存命中」计数 = **有缓存收益、且未因切换丢缓存的请求次数**（不是缓存 token 量）。
- 客户端不带 `x-session-id`：功能完全正常，但每个请求都重新调度，粘性与缓存收益丢失。

## 调度规则（怎么选 Key）

候选 = `active` 状态的 Key；优先选当前并发未达上限（`concurrencyPerKey`，默认 5）的，全部满载时放宽。候选内排序：

1. **drain 优先（用完丢弃）**：月窗用量 ≥ 80%，或距月窗重置（= 订阅续费日）≤ 72 小时且尚有剩余——这些 Key 的缓存在月窗重置时反正要丢，优先把它们用完榨干；drain 之间按月窗重置时间近者先。
2. **其余按余量平衡**：周窗口用量低 → 5h 滚动窗口用量低 → 当前并发少。

> 历史说明：早期版本有「窗口将尽 90% 预切换」逻辑，已移除——预切换本身就会丢缓存、且 5h 窗口打满时反正会 failover，得不偿失。当前近限处理 = 粘性保持 + 429 后 failover。

## 三窗口状态机

每把 Key 有 5h 滚动 / 每周 / 每月三个用量窗口（`/usage` 每 15 分钟轮询，可调），状态机：

```
录入校验通过 -> active（可用）
  |-- 5h 滚动窗口打满 -------> cooldown_rolling（到点自动恢复）
  |-- 周窗口打满 -------------> cooldown_weekly（到点自动恢复）
  |-- 月窗口耗尽 -------------> quarantined（按月窗 resetsAt 时钟自动复查回池）
  |-- 手动停用 ---------------> quarantined（reason=manual，手动启用恢复）
  |-- 401 / 退订 -------------> invalid（需手动删除重录）
```

- 冷却类状态到点自动恢复（`recover` 事件）；月窗隔离的 Key 在 `monthly.resetsAt` 过点后由轮询/复查自动放回（有 5 分钟缓冲防时钟误差）。
- 手动「启用」/ 隔离区「一键恢复」会**实时查询上游**再放行：月窗未恢复就不放（防止放回去立刻 429）；401 则直接标 `invalid`。

## 同池检测

上游 429 响应的 metadata 带 workspace id。多把 Key 若解析出**同一 workspace**，仪表盘标记「同池」并告警——它们共享同一个额度池，轮换无效，等于一把 Key。

## 空回复重试优化（`retryEmptyResponse`，默认开）

上游偶发「长思考后空回复」（`finish_reason=other` 或直接断流、零正文），多数客户端（含 ZCode）会判定 `empty_model_response` 且不重试。网关的对策：

- 收到第一个正文/工具调用前**缓冲整条流**；若最终是空回复，以**零字节断连**收尾——客户端视为连接层失败，走网络级自动重试。
- 正常出正文则按序交还思考+正文，之后完全直通。
- 已知取舍：缓冲期间思考内容不实时滚动（正文出现时一并显示）；「正文中途截断」不在覆盖范围。
- 可在设置页关闭，关闭后完全透明直通（回到原始行为）。

## 备用通道（通用 OpenAI 协议兜底）

- **触发条件**：候选集合（非 `invalid`、非手动停用）中**没有任何 `active` Key**——即三窗口语义下全部 Key 不可用时。触发判定用本地状态，请求路径零额外网络往返。
- **转发行为**：`model` 一律改写为备用通道配置的模型；请求体按 OpenAI 标准字段白名单重建（`messages/stream/temperature/top_p/max_tokens/stop/tools/tool_choice/response_format/reasoning_effort/presence_penalty/frequency_penalty/seed/user` 等），剔除 Go 平台私有扩展字段；思考强度按配置注入 `reasoning_effort`（`reasoningEffort` 默认 `max` 拉满——Agent 场景官方推荐档，各厂取值不同，留空则透传客户端值）；流式请求注入 `include_usage`（上游 400 报错则去掉注入重试一次）。
- **自动切回**：任何一把 Go Key 恢复 `active`（窗口重置复查、轮询发现、手动恢复），下一个请求立刻切回 Go（事件 `fallback:end`，via=go-recovered）。宪法：**优先保证体验（Go 订阅额度），备用只花必要的钱**。
- **计费（`billingMode=balance`，DeepSeek 官方模式）**：金额唯一口径 = 官方 `/user/balance` 余额快照差值（人民币）。切进备用时快照一次、切回时快照一次，差值即本周期实际花费；每 15 分钟定时采样 + 仪表盘「立刻计算」按钮；网关关闭时有未结算周期，下次启动自动补结算（差值入账）。token 明细仅作参考，不用 token 估算金额。
- **`billingMode=none`**：任何不支持余额查询的 OpenAI 兼容端点（如火山方舟）选此项——不计费、不显示费用区，功能不受影响。

## 存储（keys.json）

- 位置：网关脚本目录下的 `keys.json`（`GO_STATE_DIR` 可重定位）；写入时 `chmod 0600`，原子写。
- 内容：配置（调度参数、备用通道）、Key 列表与状态、会话绑定表、事件日志、备用通道运行态（快照/采样/结算记录）。
- **真实 Key 只存在这个运行时文件里**，已 `.gitignore`，任何源码与文档不含真实密钥。
